# Deploying to Render (one web service + a cron job)

Test networks only (Sepolia). Every key is a test key. Card checkout, identity checks and the payout rails stay
simulated and labelled. Not deployed yet: these are the steps.

## What runs

`render.yaml` (a Render Blueprint) defines:

- **`tethran`**: one web service with a 1 GB persistent disk mounted at `.demo-data` (the SQLite databases, uploads,
  logs). Its start command (`services/backend/scripts/render-start.ts`) runs:
  - a **gateway** on Render's `$PORT`, started first so the health check (`/healthz`) passes at once. It routes
    `/api/*` to the backend, `/signer/*` to the demo signer and everything else to the built web app. With
    `SITE_PASSWORD` set, every path except `/healthz` and the cron endpoint needs that password (basic auth, user
    `SITE_USER`, default `tethran`);
  - the **Policy Service**, the **backend** (with the Settlement Agent: live model, labelled replay fallback), the
    **demo signer** and the **web app**, all on 127.0.0.1 inside the service. The Policy Service and its key are never
    reachable from outside.
- **`tethran-jobs`**: a cron job, hourly, that calls `POST /api/jobs/run` with `JOBS_TOKEN` over Render's private
  network: invoice reminders, the exchange-rate refresh and notifications. Inside the web service the hourly timers
  are off (`JOBS_IN_PROCESS=0`, set automatically when `JOBS_TOKEN` exists), so the jobs never run twice.

First start: the disk is empty, so the service seeds the demo on Sepolia (about 40 minutes; the site shows "Tethran is
starting" until then) and then serves. Later starts and deploys serve the seeded state.

## Cost (check Render's current prices)

- Web service **Standard** (2 GB). Measured locally, the whole stack uses about 430 to 480 MB idle; the 512 MB Starter
  plan would be too tight once a settlement and the live model run.
- Disk: 1 GB.
- Cron job: billed per run time (seconds per hour).
- The free plan does not fit: no persistent disk, and it sleeps.

## Steps

1. **Push** the repository to GitHub (main). Render deploys from the repository.
2. In Render: **New > Blueprint**, pick the repository. It reads `render.yaml` and proposes `tethran` and
   `tethran-jobs`.
3. Fill in every `sync: false` value (copy from your local `.env`; never paste them anywhere else):
   `TREASURY_PRIVATE_KEY`, `AGENT_SIGNER_PRIVATE_KEY`, `POLICY_SIGNER_PRIVATE_KEY`, `OPERATOR_PRIVATE_KEY`,
   `ARBITER_PRIVATE_KEY`, `PROVIDER_PRIVATE_KEY`, `DEMO_WALLET_SEED`, `RPC_URL_11155111`, `GROQ_API_KEY`,
   `GROQ_MODEL`, `GEMINI_API_KEY`, `GEMINI_MODEL`, `LLM_PROVIDER_ORDER`, `OPIK_API_KEY`, `OPIK_WORKSPACE`,
   `OPIK_PROJECT_NAME`, `EMAIL_PROVIDER`, `EMAIL_API_KEY`, `EMAIL_FROM`, `VITE_REOWN_PROJECT_ID`, and a strong
   `SITE_PASSWORD`. `JOBS_TOKEN` is generated by Render and shared with the cron job.
4. **Apply.** The build installs the five packages and builds the web app (about 3 to 5 minutes). The first start
   then seeds (about 40 minutes). Watch the logs for `services ready`.
5. Open `https://<service>.onrender.com`, sign in with `tethran` and `SITE_PASSWORD`.
6. Allow the domain: in the Reown dashboard (wallet connection) add `<service>.onrender.com`; in Resend, `EMAIL_FROM`
   must be on a verified domain.
7. Check the cron job: run `tethran-jobs` once from the dashboard ("Trigger Run"); its log shows
   `{"ran_at":…,"fx_refresh":"ok","reminders":"ok"}`.

Pay links and email links use the service's public URL automatically (`RENDER_EXTERNAL_URL`); the backend and the
demo signer accept requests only from that origin.

## Operating it

- **Reseed** (fresh demo state): set `RESEED=1`, deploy, wait for `services ready`, then remove `RESEED` (otherwise
  every restart reseeds). Test USDT and Sepolia ETH come from the treasury: check its balance first.
- **Changing a `VITE_*` value** needs a new deploy (they are fixed at build time).
- **One instance only** (the disk belongs to one instance); a deploy has a short downtime while it restarts.
- **Long requests**: a settlement can wait on Sepolia for minutes. The gateway has no timeout of its own; if Render's
  proxy cuts a long request, reload the page: the work continues on the server and the page picks it up.
- **If the cron cannot reach the service** over the private network, change its command to the public URL:
  `curl -fsS -X POST -H "x-jobs-token: $JOBS_TOKEN" https://<service>.onrender.com/api/jobs/run`.

## Risks

- **The demo signer** signs as the operator, the arbiter and the provider with test keys. Keep `SITE_PASSWORD` set;
  share it only with judges. Without it, anyone could change the vault limits or decide disputes (test funds only, but
  it can wreck a live demo and spend the treasury's Sepolia ETH).
- **Minting** (Add funds, Get test USDT) costs the treasury Sepolia ETH; per-IP limits apply.
- **Email** goes to any address entered unless `EMAIL_RECIPIENT_ALLOWLIST` is set; the daily cap bounds it.
